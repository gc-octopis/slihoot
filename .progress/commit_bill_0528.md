# feat: 簡答題批改、作答流程調整與已作答鎖定

## 摘要

這次提交主要圍繞「計時作答」與「公布答案」的流程，讓主持人對節奏有更明確的掌控，並補上簡答題的正確答案與批改。包含以下幾個面向：

- 題目設定：是非題／選擇題必須設定正確答案才能新增，簡答題補上正確答案欄位，新增題目可設定作答秒數。
- 簡答題的正確答案設定與自動批改。
- 調整開始作答流程：只有第一題需要手動按「開始答題」。
- 計時與公布答案：倒數結束才公布答案，時間到後參與者端會顯示詳解與正確答案。
- 文字雲顯示倒數計時，計時內可無限次送出，時間到鎖定並公布結果。
- 已作答過的題目在重新切換時鎖定，不可再次作答。

## 題目設定

- 是非題與選擇題現在必須設定正確答案才能新增或儲存（先前未設定答案也能新增）。
- 簡答題新增「正確答案」欄位（先前完全沒有可填答案的地方）。
- 新增題目時可設定「作答秒數」（先前沒有秒數設定），`0` 表示不限時。
- 設定作答秒數後，倒數跑完時參與者端會顯示詳解與正確答案。

## 簡答題正確答案與批改

- `normalizeCorrectAnswer` 支援 `short_answer` 型別，儲存標準答案文字。
- 題目編輯頁新增「正確答案」欄位，題目列表也會顯示已設定的正解。
- `getResponseSummary` 對簡答題進行批改，計算答對人數並標記每筆作答正確或錯誤。
- 參與者端在公布答案後會看到正確答案，以及自己作答的正確／錯誤判定。

## 作答流程

- `startLiveSession` 啟動時，第一題不再自動開始，需主持人手動按「開始答題」。
- 新增 `startActivity` 與 `start_activity` WebSocket 事件，用於開始當前題目的計時。
- 按「下一題」切換到尚未作答過的題目時會自動開始，主持人不需要每題都再按一次「開始答題」。
- 參與者在主持人尚未開始該題前看不到題目內容，畫面顯示等待提示。

## 計時與公布答案

- `getLiveState` 重新整理為 `activityOpen`、`answerRevealed`、`answerClosed` 三個狀態。
- 限時題在倒數結束（時間到）後才會公布答案；不限時題才透過「顯示結果」公布。
- 參與者端只有在 `answerRevealed` 為真時才會收到結果摘要，倒數進行中不會提前外洩。
- 倒數結束（時間到）後，參與者端會顯示該題的詳解與正確答案。
- 主持人的「顯示結果」按鈕在倒數進行中為停用狀態，倒數結束才能使用。

## 文字雲

- 文字雲會顯示倒數計時。
- 倒數時間內可無限次送出多個詞（不會因送出一次就鎖定）。
- 倒數結束後鎖定輸入並公布文字雲結果。

## 已作答鎖定

- `live_sessions` 新增 `completed_activity_ids` 欄位，記錄已開始（作答）過的題目。
- 切換題目時，離開的題目會被加入已完成清單。
- 重新切回已完成的題目時鎖定作答（含文字雲），並維持公布答案／詳解的顯示。

## UI 調整

- 題目未設定正確答案時，改以 `window.alert` 跳出警告，取代原本不明顯的橫幅提示。
- 選擇題公布答案後，會同時標示正解與參與者自己選的錯誤選項。
- 新增 `.choice.wrong`、`.answer-reveal`、`.verdict` 等樣式。

## 驗證

- `bunx tsc --noEmit` 通過。
- `bunx vite build` 通過。
- 因 live 流程需連線 MySQL 後端，尚未在瀏覽器端完整跑過實際操作。

## 注意事項

- `completed_activity_ids` 欄位由啟動時的自動遷移加入，伺服器需重新啟動才會套用。
